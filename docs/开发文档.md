## 1. 项目概述

HomeHealth 是一个面向多成员家庭的健康档案管理 Android 应用。用户可以通过拍照或上传体检报告、化验单、处方等医疗文档，应用自动提取结构化健康指标（如血压、血糖、胆固醇等），建立家庭健康档案，并基于历史数据进行趋势分析、异常预警和健康问答。

核心特性：
- 多成员家庭管理，每个成员拥有独立健康档案。
- 文档上传（拍照/相册），OCR + LLM 解析为结构化数据。
- 本地优先存储，保护隐私。
- 历史趋势对比，主动异常预警。
- 基于个人健康数据的问答（当前实现为**记录注入式问答**；医学知识库检索 + RAG 属规划项，尚未实现）。
- 用药提醒与健康任务管理。

## 2. 技术栈

### 2.1 Android 端
- **语言**：Kotlin
- **最低 SDK**：26 (Android 8.0)
- **UI 框架**：Jetpack Compose (推荐) 或 XML Views
- **架构**：MVVM + Repository
- **本地数据库**：Room (结构化数据) + SQLite
- **文件存储**：内部存储 / MediaStore
- **网络**：Retrofit + OkHttp (用于调用远程 LLM/OCR 服务)
- **图片处理**：CameraX, Coil
- **后台任务**：WorkManager (定时任务、数据同步)
- **通知**：NotificationManager
- **依赖注入**：Hilt
- **协程**：Kotlin Coroutines + Flow

### 2.2 后端 / AI 服务
- 可选择两种模式：
  - **云端模式**：调用远程 API（如 OpenAI GPT-4V、Google Cloud Vision、自定义服务）
  - **本地模式**：使用 Ollama 运行本地 LLM，Tesseract 本地 OCR（性能要求较高，适合高端设备）
- 推荐 MVP 使用云端 API，后期可扩展本地推理。

### 2.3 数据存储
- **结构化数据**：Room 数据库存储成员、健康指标、文档元数据、提醒等。
- **原始文档**：以文件形式存储在应用私有目录或外部存储（用户授权）。
- **向量数据库**：可选，用于医学知识库 RAG。可使用本地向量库（如 ObjectBox、SQLite + FTS）或远程向量库（Pinecone, Qdrant）。MVP 阶段可使用简单关键字匹配或远程 API。

## 3. 系统架构

采用典型 Android 分层架构：

```
┌─────────────────────────────┐
│         Presentation        │  Compose UI, ViewModel
├─────────────────────────────┤
│           Domain            │  Use Cases, Models
├─────────────────────────────┤
│            Data             │  Repository, Data Sources
│  ┌──────────┬─────────────┐ │
│  │ Local DB │ Remote API  │ │
│  └──────────┴─────────────┘ │
└─────────────────────────────┘
```

**模块划分**：
- `app`：主应用模块
- `core`：通用工具、扩展
- `data`：数据层（Room, Retrofit, Repository 实现）
- `domain`：业务逻辑与模型
- `feature`：按功能划分（如 `healthrecord`, `document`, `alert`, `qa`）

### 4.2 HealthRecord（健康指标记录）
```kotlin
@Entity(tableName = "health_records",
        foreignKeys = [ForeignKey(entity = FamilyMember::class, parentColumns = ["id"], childColumns = ["memberId"], onDelete = CASCADE)],
        indices = [Index("memberId"), Index("type")])
data class HealthRecord(
    @PrimaryKey val id: String,
    val memberId: String,
    val type: String, // 如 "blood_pressure", "blood_glucose", "cholesterol", "weight"
    val value: String, // 存储原始值或结构化 JSON，如 "120/80"
    val numericValue: Double?, // 用于趋势分析的主数值，如收缩压
    val unit: String, // 如 "mmHg", "mmol/L"
    val recordDate: Long, // timestamp
    val sourceDocumentId: String?, // 关联的文档 ID
    val notes: String?
)
```

## 5. API 设计（后端服务）

如果使用云端服务，需要定义接口。MVP 阶段可自建简单后端（如 Firebase Functions 或 FastAPI）代理 LLM 和 OCR 调用。

### 5.1 OCR + 结构化提取
**端点**：`POST /api/documents/parse`

请求：
```json
{
  "image_base64": "...", // 或文件上传 multipart
  "member_id": "xxx",
  "document_type": "lab_report" // 可选
}
```

响应：
```json
{
  "status": "success",
  "extracted_data": {
    "records": [
      {
        "type": "blood_pressure",
        "value": "120/80",
        "numeric_value": 120,
        "unit": "mmHg",
        "date": "2025-01-15"
      }
    ],
    "raw_text": "OCR 原始文本"
  }
}
```

### 5.2 健康问答（规划：RAG；当前实现为记录注入式）
**端点**：`POST /api/qa/ask`

请求：
```json
{
  "member_id": "xxx",
  "question": "我妈妈最近血压怎么样？"
}
```

响应：
```json
{
  "answer": "根据记录，您母亲最近三次血压分别为...",
  "sources": ["记录1", "记录2"],
  "references": ["医学指南链接"]
}
```

### 5.3 异常检测（可选，若后端处理）
**端点**：`POST /api/analytics/detect` 或由客户端本地计算。

## 6. Android 应用详细设计

### 6.1 主要界面

1. **家庭列表页**：展示家庭成员卡片，点击进入个人健康档案。
2. **个人档案页**：展示该成员的健康指标概览、最近记录、趋势图、预警列表。
3. **文档上传页**：拍照或从相册选择，上传后显示解析进度。
4. **指标详情页**：展示某一指标的历史数据和趋势图，可手动添加记录。
5. **预警中心**：列出所有预警，按严重程度排序。
6. **用药提醒页**：管理提醒，添加/编辑/删除。
7. **问答页面**：聊天界面，用户提问，显示回答及来源。
8. **设置页**：家庭成员管理、数据导出、隐私设置。

### 6.2 关键流程实现

#### 6.2.1 文档上传与解析流程
1. 用户点击“上传报告”，选择拍照或相册。
2. 应用压缩图片（可选），上传至服务器（或调用本地 OCR）。
3. 服务器返回 OCR 原始文本和结构化记录列表。
4. 应用将结构化记录展示给用户确认（可编辑）。
5. 用户确认后，记录存入 Room 数据库，文档文件保存本地，状态标记为 COMPLETED。
6. 同时触发异常检测逻辑，生成预警（如有异常）。

**代码结构建议**：
- `DocumentUploadViewModel`：处理 UI 状态。
- `DocumentRepository`：管理上传和解析调用。
- `HealthRecordRepository`：保存记录。
- `AlertRepository`：生成预警。

#### 6.2.2 历史趋势与异常检测
- 定期（或每次新增记录后）检查该成员的健康指标是否超出正常范围或趋势异常。
- 异常检测可基于简单规则（如血压 > 140/90）或统计方法（如连续上升）。
- 生成 `Alert` 记录，并通过 `NotificationManager` 推送通知。
- 使用 `WorkManager` 每日检查一次，并支持立即检查。

#### 6.2.3 健康问答（规划：RAG；当前实现为记录注入式）
- 用户输入问题，应用将 `member_id` 和问题发送到后端。
- 后端先检索该成员近期健康记录（作为上下文），再结合医学知识库（向量检索）生成回答。
- 应用显示回答和引用来源。
- 若使用本地模型，则在设备端调用 Ollama，但 MVP 建议远程。

### 6.3 数据存储实现细节

- **Room 数据库**：定义 DAO 接口，例如 `HealthRecordDao` 提供按成员和类型查询最近 N 条记录的方法。
- **文件存储**：使用 `context.filesDir` 或 `MediaStore` 保存原始图片，数据库存储文件路径。
- **数据导出**：可导出为 JSON 或 CSV，通过分享 Intent 发送。

### 6.4 通知与后台任务

- **WorkManager** 定时任务（每日一次）：
  - 检查用药提醒，发送通知。
  - 检查健康数据，执行异常检测。
- 通知点击后跳转到对应界面（如个人档案或预警中心）。

### 6.5 权限

- 相机权限：用于拍照上传。
- 存储权限（Android 13+ 使用系统文件选择器，无需权限）。
- 通知权限（Android 13+ 需要运行时请求 `POST_NOTIFICATIONS`）。

### 9.3 异常检测 UseCase 示例

```kotlin
class DetectAnomaliesUseCase @Inject constructor(
    private val healthRecordRepository: HealthRecordRepository,
    private val alertRepository: AlertRepository
) {
    suspend operator fun invoke(memberId: String) {
        val recentRecords = healthRecordRepository.getRecentRecords(memberId)
        // 规则示例：血压收缩压 > 140 或 < 90
        recentRecords.filter { it.type == "blood_pressure" }.forEach { record ->
            val systolic = record.numericValue ?: return@forEach
            if (systolic > 140) {
                alertRepository.createAlert(
                    Alert(
                        id = UUID.randomUUID().toString(),
                        memberId = memberId,
                        type = "out_of_range",
                        title = "血压偏高",
                        description = "收缩压 ${systolic} mmHg 超出正常范围",
                        severity = AlertSeverity.HIGH,
                        createdDate = System.currentTimeMillis(),
                        isRead = false
                    )
                )
            }
        }
    }
}
```
